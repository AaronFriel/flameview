# Flameview Snapshot Playbook

Use this playbook to add and maintain snapshot-style interactive UI tests.

## Existing Snapshot Surface

Current snapshots are generated by unit tests in:

- `crates/cli/src/viewer/app.rs`

Snapshot artifacts are stored in:

- `crates/cli/src/viewer/snapshots/*.snap`

## Add a New Interactive Snapshot

1. Add a new test under `#[cfg(all(test, not(miri)))]` in `crates/cli/src/viewer/app.rs`.
2. Build a deterministic folded-stack fixture in-memory (string literal + `load_stream`).
3. Create `App::new(&tree)`.
4. Replay key events using `app.on_key(KeyCode::...)` in the exact interaction order.
5. Capture output with `app.snapshot_text(view_rows, name_width)`.
6. Assert with `insta::assert_snapshot!("name", snapshot)`.

## Review and Update Cycle

1. Run check mode:

       <repo-root>/.codex/skills/flameview-tui-snapshot/scripts/tui_snapshots.sh check <repo-root>

2. If failures are intentional, update snapshots:

       <repo-root>/.codex/skills/flameview-tui-snapshot/scripts/tui_snapshots.sh update <repo-root>

3. Re-run check mode and then `cargo test --package flameview-cli`.

## Determinism Guidelines

- Keep fixtures small and explicit; do not read random external files in snapshot tests.
- Avoid time-based values or host-dependent paths in snapshot text.
- Keep viewport dimensions fixed in `snapshot_text` calls.
- Prefer stable key sequences that represent meaningful user workflows (filter + search + sort + expand).
